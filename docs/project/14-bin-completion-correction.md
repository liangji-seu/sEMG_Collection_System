# 完整bin同步与旧配对纠错（2026-10-07）

本次依据用户提供的L062、L075、L372原始文件纠错，基线为`232f0b2 / v2.1.0-codex`。此前自动回归通过没有覆盖完整bin的首尾缺BLE场景，不能据此声称该契约已实现。

## 1. 为什么此前仍有“丢帧”

- 兼容入口`sync_h5_with_bin`保留了旧的逐BLE行×8构建循环，仍会跳过未收到BLE包的SD帧，并存在缺帧填充与失效变量分支。现在委托统一一对一实现，删除旧循环。
- 新共享枚举器补上BLE中间缺包区间，却仍按首尾BLE锚点裁剪bin；只为prompt延长尾部，不等于全量保留配对bin。
- 旧`ble_anchored_extended`标记被视为完成证据，无法证明输出完整；现在按明确的输出契约版本与来源/输出帧数判定升级，旧结果允许重新同步。
- 之前合成样本大多让BLE锚点恰好覆盖bin首尾；有界prompt测试还把一对一裁剪固定成预期。本次补充缺头、缺尾、大量内部丢BLE及历史输出升级测试。

## 2. 修复后的契约

一对一：输出配对bin中所有真实EMG样本，每个样本恰好一次；仅bin实际不存在的样本保留缺口，不使用前值、零值或BLE值伪造。源样本数与输出样本数写入审计属性。

BLE只提供数据身份/坐标与时间锚点：实际锚点时间不被全局直线拟合挪走，锚点间按真实SD帧号插值；首尾缺BLE部分以1/2000秒间隔外推。不以H5的start/end或prompt裁剪完整配对bin。

一对多：共享长bin仍按ADC匹配到的明确会话区间输出，避免其他会话数据进入当前H5。多源rescue保留逐段范围与来源元数据。

正对齐偏移可能令真实bin前缀早于H5的SD计数器0。此时EMG输出`sd_frame_id`使用int64保存负标签，不钳零、不丢弃、不无符号回绕，保持`真实bin帧号 = sd_frame_id + sync_bin_align_offset`。旧数据集若dtype或容量不兼容，在离线事务内重建并保留属性。IMU推导不把负EMG标签转成巨大无符号ID。

输出新增`sync_output_contract_version=2`、`sync_full_bin_preserved`、`sync_source_frame_count`、`sync_output_frame_count`和时间来源说明。下游独立分析脚本应按字段名读取并支持上述有符号标签。

## 3. L372失败诊断

实际提供的是`session4_20260903_155823.h5`，其旧属性引用左`155549`、右`155550`，而配对文件为左`155821`、右`155822`。

- 原GUI仅按旧属性找文件，在本次bug样本目录中两侧都返回`(None,None)`；在包含旧bin的大目录中则可能选到前一轮数据。旧错误中相关系数约0.4086，没有达到校验要求。
- 显式使用本次提供的正确配对bin时，已发布基线和本次代码均能通过ADC验证；因此不能把这次失败归为EMG数据损坏，也不能把新全量枚举误称为ADC匹配修复。
- 左侧为8点均值模型、偏移-15；右侧同为8点均值模型，bin全局首帧为578415，按该非零基准定位；验证窗口逐采样命中率100%。
- GUI增加受限候选解析：仅一对一且开启ADC校验，按同受试者/左右侧/日期及H5会话时间寻找10秒内唯一最近候选；替换过期/缺失引用并记录原因，最终仍须ADC强校验。歧义不猜；无可靠候选时保留已有属性引用供ADC检查。关闭校验及一对多保持旧引用规则。非标准H5文件名不破坏有效旧引用。

提供目录未包含旧`155549/155550`的bin，因此没有重放当时实际误选文件的ADC内容；已复现的是自动选源缺陷及正确配对的成功。其他300+受试者的每条失败需分别检查源文件，不能由L372一个例子推断全部同因。
