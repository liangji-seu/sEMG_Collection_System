# 手环固件 5.3.0 BLE 包格式适配（2026-10-30）

## 现象

现场两只手环（`WristBand_C752` / `WristBand_CCA6`，固件 `V5.3.0`）连上后
UI 显示"已连接 / 预览中 / IMU 2/3"，但 EMG1、EMG2 的 `Frames` 都是 0，波形空白。

`log/server_20261030_103346.965_102344_000001.log` 里 47 秒内：

- `包过短: 408, 期望至少 436` × 2463
- `包过短: 372, 期望至少 436` × 343
- `包过短: 336, 期望至少 436` × 2
- `IMU 数据异常: 44 bytes (非 18 的倍数)` × 593、`8 bytes` × 26
- `EMG_CAPTURE_HEALTH ... "total_frames": 0, "last_valid_emg_age_s": null`

通知回调一直在触发（`last_valid_notification_age_s ≈ 0.015`），说明 BLE 链路正常，
是**解析器把每个包都整包丢掉**了。

## 根因

旧解析器按 5.2 及以前的固定布局解析：

```
4B 包号 + 9 帧 × 16ch × 3B(24bit) = 436 + N×18B IMU 快照
```

5.3.0 固件改成了"可变 EMG 帧数 + IMU 实时尾包"：

```
4B 包号 + N 帧 × 16ch × bps
        + magic(0xA55A, u16) + imu_seq(u32) + count(u8) + num_imus(u8)
        + count × num_imus × 18B
```

- `N` 不再固定：现场 250Hz BLE + 120Hz IMU 下主要是 6 帧/包，偶尔 9 帧；
- `count` 是这一包携带的 IMU 样本数（0..3），每包不同；
- 因此包长只有 336 / 372 / 408 / 444 / 480 几种，全部小于旧的 436 门槛。

用真实抓包验证：`MTU=500`，153 个通知全部为 `12 + 36n` 结构，
即 `4+6×48+8+k×2×18`（k=1..3）与 `4+9×48+8+k×2×18`（k=0..1），与上面的公式完全吻合。

## 修复

1. **ble_server: 按包识别布局**（`_detect_packet_layout`）
   - 先按 5.3 尾包识别：扫描 `bps∈{3,2}`、`num_imus∈1..3`、`count∈0..8`，
     要求 `magic/count/num_imus` 三者一致，才认定 5.3 布局；
   - 无尾包时按长度反推 EMG 帧数（IMU 关闭场景）；
   - 都不匹配再回落到旧的"9 帧 + 18B×N"逻辑，**旧固件行为不变**。
2. **帧号改用游标**（`_next_frame_cursor`）
   每包帧数可变后，`帧号 = 包号 × 固定帧数` 会漂移；改为按上一包末尾续写，
   用包序号检测丢包并按上一包帧数补偿，计数器复位时继续往后走（不倒退）。
3. **一包多帧 IMU**
   解析出 `imu_all`（展平的 `{index, acc, gyr, mag}`）与等长的 `imu_t`；
   样本内时刻按状态快照里的 `imu_sample_rate_hz`（现场为 120Hz）从包尾回推，
   并保证跨包单调。Node 写入时优先用 `imu_all`，存储侧按行写各自时间戳。
4. **状态快照格式修正**
   旧格式少了 `usb_drop` 一个 `I`，导致固件/硬件版本字段整体错位；
   同时补读 V2/V3 尾部扩展（BLE 速率、IMU 采样率、标称每包帧数）。
   现在日志可直接看到 `固件 V5.3.0 BLE速率=250Hz IMU=120Hz 标称每包EMG帧数=6`。

## 验证

- 单机抓包（`tmp/probe_ble_packet.py`）：153/153 包解析成功，918 帧、874 行 IMU；
- 端到端（`tmp/e2e_preview_probe.js`，起完整 server + 真实手环）：
  两只手环连接成功，`start_preview_stream` 返回 `started:[1,2]`；
  6 秒内前端收到 399 个 `realtime_data_batch`，EMG1 193 段 / 1158 帧、
  EMG2 254 段 / 1524 帧、IMU 399 段，全部带数据；
- 回归：Python 185 项、Node 110 项全部通过（新增 8 项 5.3 解析/写入用例）。

## 注意

- 5.3 固件的 IMU 是 120Hz（状态快照上报），IMU 时间戳按 120Hz 展开；
- 16bit 模式在部分帧数下与 24bit 存在长度歧义，识别顺序优先 24bit
  （与供应商上位机一致），当前现场用的是 24bit。
