# 双侧 EMG 时间轴复核（2026-10-11）

## 复核范围与结论

复核 L057 的 `20260719_145539` 与先前报错的 `20260719_145353`。两侧同步分别读取自己的 BLE 和 BIN；逐锚点 ADC 与自身 BIN 的 16 通道均精确一致，没有发现左右锚点混用。问题在时间证据：逐个 BLE 时间插值会把接收时间的抖动传递给完整的 2 kHz 输出。

之前 157 个文件的现场验收验证了样本完整性、来源一致性、时间有限且严格递增。这些检查不能证明时间轴没有拉伸，也不能证明两侧达到物理同步精度。

`残差 = BLE 时间 - [本侧首锚点时间 + (本侧匹配 BIN 帧号 - 本侧首匹配 BIN 帧号) / 2000]`

145539 左侧残差从峰值回落约 839.130 ms，说明至少存在明显的时间抖动，不能用累计采样暂停解释全部偏差。145353 左侧残差则基本单调增加，仅凭现存数据无法区分传输延迟与真实采样暂停。

## 时间信息的局限

采集日期附近的历史代码以 BLE 通知到达电脑的时间为参考，并按包内帧数回推时间；高精度电脑时钟也不能消除 BLE 传输延迟。未在这两组 H5/BIN 中确认到固件逐采样的真实硬件时间字段。提交时间只能说明历史代码行为，不能单独证明现场运行了哪个版本。

当前正常同步输出精确经过各自 BLE 时间锚点，首尾按标称 2 kHz 外推。这能证明使用了正确的本侧时间字段，不能证明这些字段就是准确的采样时间。双侧标定预览使用各自 `time` 列和共享会话时间原点，没有发现额外平移左手波形的代码。

## 对比副本

另行生成独立副本，用每侧自身第一个精确匹配 BLE 锚点确定起点，后续按该侧 BIN 帧号差除以 2000 展开。该方案保留真实帧号缺口对应的时间跨度，不按输出行号压缩缺口，不参考另一侧信号，不用肌电波形相关性强行平移。

此时间轴明确假设设备持续以 2 kHz 采样，且没有未记录的真实采样暂停。首 BLE 锚点本身的传输延迟仍无法恢复。对比副本用于排查可视滞后，不代表硬件同步精度已经得到验证；保留原 BLE 时间、全部 ADC/帧号和 IMU。145353 只采用已匹配到对应 BIN 的首 BLE epoch，不把后续重启记录误作时间锚点。

诊断与对比产物在 `tmp/field-validation-20261011/`。对比副本分别位于 `counter-clock-comparison/145353/` 和 `counter-clock-comparison/145539/`，文件名沿用输入文件名。两份均完成验收：四个首锚点唯一精确匹配，所有非时间字段和其他数据集一致，新增 `clock_comparison_only=True` 标记。
